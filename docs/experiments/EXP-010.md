# EXP-010 — Disambiguating Description Edits on Near-Duplicate Surfaces (follow-up to EXP-003)

**Status:** preregistered and approved (2026-10-28); gold validated; **not run: ceiling check failed for both models (2026-10-28)**  
**Milestone:** M3 follow-up  
**Label:** all numbers below are plans or come from earlier results files, which are cited.

---

## Question
Can rewriting near-duplicate tool descriptions to say when to use each one raise accuracy, and what does it cost in tokens?

## Why
EXP-003 could not show any edit helping: goodserver was already at 100% (`results/exp003_analysis.json`). Near-duplicate surfaces sit at 25–37% (EXP-001 follow-up), leaving room to improve.

## Hypotheses
- **H1 (confirmatory):** A *contrast clause* ("Use this for X. For Y, use `<other tool>`.") added to every tool on a surface raises accuracy versus the base surface.
- **H2 (confirmatory):** A *negation clause* ("Do not use this for Y.") added to every tool raises accuracy versus base.
- **H3 (exploratory):** The contrast clause beats the negation clause.

## Design

| Factor | Values |
|---|---|
| Surfaces | the 4 near-duplicate surfaces from EXP-009, each as: base, `+contrast`, `+negation` |
| Cases | the 32 families from EXP-009 |
| Orderings | 4 balanced orderings per surface (each tool once in each position), the same for every condition, to keep position from confounding the edit |
| Models | `openai/gpt-oss-20b`, `openai/gpt-oss-120b` |
| Temperature | 0 |

Total: 32 × 3 conditions × 4 orderings × 2 models = **768 trials** (base trials overlap EXP-009 and are reused where the ordering matches).

## Edits
Generated by `scripts/gen_followup_fixtures.py` from one short scope phrase per tool, written from the base descriptions alone, and committed as `fixtures/surfaces/nd_<name>_contrast.json` and `_negation.json` **before any case is run**. Every clause restates behaviour already in the base descriptions, so the edit clarifies rather than adds capability (checked by `tests/test_followup_fixtures.py`).
- **Contrast:** "Use this for <scope>. For <other scope>, use `<other tool>`." for each of the three other tools.
- **Negation:** "Do not use this for <scope A>, <scope B> or <scope C>."

## Ceiling check
The base descriptions already state each tool's scope, so the models may get near 100% without help, as on goodserver in EXP-003. Before EXP-010 runs, base accuracy is read from EXP-009's trials at the same orderings; if a model's base accuracy on held-out families is ≥ 0.90, EXP-010 is not run for that model, and this is recorded.

## Overfitting guard
Families are split in advance, 4 per surface: tool-paired cases (one case per tool, chosen by `random.Random(42)`) go to the held-out evaluation set (16 families); the rest are train. The primary analysis uses held-out families. Limitation: the same author wrote the cases and the scope phrases, in the same session, so this guard is weak; the edits are mechanical restatements of the base descriptions, which limits how much they can be tuned to particular cases.

## Primary outcome
Paired accuracy delta, edit − base, per model, on held-out families; clustered bootstrap over families (10,000 resamples, seed 42), with McNemar on matched (family, ordering) trials reported as descriptive. Holm correction across H1 and H2.

## Verdict rule (per edit, per model)
- **helps:** delta CI lower bound > +0.05.
- **regresses:** delta CI upper bound < −0.05.
- **costs:** delta CI contains 0 and description tokens rise by more than 20% (`o200k_base`).
- **inconclusive:** otherwise.

## Sample size
16 held-out families × 4 orderings per condition. No prior estimate of the edit effect exists, so this is sized to detect a delta of about 15 pp; that assumption is [unverified] and will be checked against the observed CI.

## Budget cap
`--max-usd 5.00` per run.

## Ceiling check result (2026-10-28)
EXP-009 base accuracy (`results/exp009_analysis.json`) was 0.9987 for 20b and 0.9961 for 120b over all 32 families and 24 orderings, so held-out accuracy at any 4 orderings is also ≥ 0.90 (at most 3 wrong trials per model). By the preregistered rule EXP-010 was **not run for either model**. Description edits cannot be shown to help on surfaces the models already get right; per the ADR-023 stop rule this is final for v0.1.

- None. The runner (`scripts/run_followups.py --exp 10`) exists but was not called live.
