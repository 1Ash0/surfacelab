# EXP-010 — Disambiguating Description Edits on Near-Duplicate Surfaces (follow-up to EXP-003)

**Status:** draft preregistration — awaiting approval; edits and fixtures not yet written (ADR-023)  
**Milestone:** M3 follow-up  
**Label:** all numbers below are plans or come from earlier results files, which are cited.

---

## Question
Can rewriting near-duplicate tool descriptions to say when to use each one raise accuracy, and what does it cost in tokens?

## Why
EXP-003 could not show any edit helping: goodserver was already at 100% (`results/exp003_analysis.json`). Near-duplicate surfaces sit at 25–37% (EXP-001 follow-up), leaving room to improve.

## Hypotheses
- **H1 (confirmatory):** A *contrast clause* ("Use this for X. For Y, use `<other tool>`.") added to every tool on a surface raises accuracy versus the base surface.
- **H2 (confirmatory):** A *negation clause* ("Do not use this for Y.") added to every tool raises accuracy versus base.
- **H3 (exploratory):** The contrast clause beats the negation clause.

## Design

| Factor | Values |
|---|---|
| Surfaces | the 4 near-duplicate surfaces from EXP-009, each as: base, `+contrast`, `+negation` |
| Cases | the 32 families from EXP-009 |
| Orderings | 4 balanced orderings per surface (each tool once in each position), the same for every condition, to keep position from confounding the edit |
| Models | `openai/gpt-oss-20b`, `openai/gpt-oss-120b` |
| Temperature | 0 |

Total: 32 × 3 conditions × 4 orderings × 2 models = **768 trials** (base trials overlap EXP-009 and are reused where the ordering matches).

## Edits
Written by hand once per tool, from the tool descriptions alone, **before any case is run** on the edited surfaces, and committed as fixtures. Every clause must name only behaviour already stated in the base description of the tools involved, so the edit clarifies rather than adds capability.

## Overfitting guard
Families are split in advance, 4 per surface: tool-paired cases (one case per tool, chosen by `random.Random(42)`) go to the held-out evaluation set (16 families); the rest are train. Edit authors may look at train cases only. The primary analysis uses held-out families.

## Primary outcome
Paired accuracy delta, edit − base, per model, on held-out families; clustered bootstrap over families (10,000 resamples, seed 42), with McNemar on matched (family, ordering) trials reported as descriptive. Holm correction across H1 and H2.

## Verdict rule (per edit, per model)
- **helps:** delta CI lower bound > +0.05.
- **regresses:** delta CI upper bound < −0.05.
- **costs:** delta CI contains 0 and description tokens rise by more than 20% (`o200k_base`).
- **inconclusive:** otherwise.

## Sample size
16 held-out families × 4 orderings per condition. No prior estimate of the edit effect exists, so this is sized to detect a delta of about 15 pp; that assumption is [unverified] and will be checked against the observed CI.

`--max-usd 5.00` per run.
