# EXP-005 — Tool-Count Dose-Response

**Status:** run and analysed. **H1 and H2 not confirmed:** accuracy stays at 92–100% up to 50 distractors of every kind (see Results)  
**Milestone:** M6  
**Label:** numbers in Results trace to `results/exp005_analysis.json` (from `scripts/analyze_exp005.py`, replay only).

---

## Question
How does accuracy change as distractor tool count increases, and which distractor kind drives the drop?

## Hypotheses
- **H1 (confirmatory):** Accuracy decreases monotonically as N (distractor count) increases from 0 to 50 for `near-duplicate` distractors.
- **H2 (confirmatory):** The accuracy drop is larger for `near-duplicate` than for `unrelated` distractors at N=20.
- **H3 (exploratory):** The dose-response slope is steeper for the smaller model.

## Design

| Factor | Values |
|---|---|
| Base surface | `goodserver` |
| Distractor count (N) | 0, 5, 10, 20, 50 |
| Distractor kind | `unrelated`, `same-domain`, `near-duplicate` |
| Model | `openai/gpt-oss-20b` (Groq), `openai/gpt-oss-120b` (Groq) |
| Cases | `fixtures/cases/core.jsonl` positive + sibling cases only (12 families) |
| Variants | canonical order for target tools; distractors appended |

Total: 12 × 5 N-values × 3 kinds × 2 models = **360 trials**

## Primary outcome
Hit rate vs N per (kind, model) with 95% clustered bootstrap CI. Simple logistic curve fit per cell (if n supports it); slope with CI.

## Cost outcome
Prompt tokens per call (from cassette metadata). Plotted alongside accuracy as "accuracy per token" figure.

## Surfaces
Generated at run time via `pad_surface(goodserver, N, kind, seed=42)`. Not stored as fixtures (too many combinations). Seed is fixed and recorded.

## Confound control
The `unrelated` distractor condition with equal N controls for prompt length (same token count increase, different semantic similarity). The length-only effect is `unrelated` accuracy drop; the semantic effect is `near-duplicate` − `unrelated`.

## Sample size
12 families × 5 N-values × 3 kinds = 180 (family, condition) cells per model. Clustered CI within each condition (12 families per cell) will be wide (~0.14 half-width) but adequate for detecting a > 0.20 difference between conditions.

## Analysis plan
1. Run all 360 trials.
2. Plot hit rate vs N for each (kind, model) combination.
3. Fit logistic curve per cell; report slope and CI. Do not fit if fewer than 3 N-values have n > 5 families.
4. Compute H2 contrast: acc(N=20, near-duplicate) − acc(N=20, unrelated) with McNemar on matched families.

## Verdict rule
- **H1 confirmed:** logistic slope for `near-duplicate` CI entirely < 0 (accuracy decreasing).
- **H2 confirmed:** contrast CI lower bound > 0.05.

## Budget cap
`--max-usd 5.00`

## Deviations
1. **Temperature 0**; not specified in the plan. See EXP-001 deviation 1.
2. **Run with `scripts/run_exp005.py`, not `surfacelab run`.** The CLI only loads saved fixture surfaces; the script builds the padded surfaces at run time as the plan requires, with the same dry-run estimate, `--max-usd` cap and cassettes.
3. **H2 contrast sign.** The plan writes the contrast as acc(near-duplicate) − acc(unrelated) but confirms H2 when its lower bound exceeds +0.05; that can never pass if near-duplicates hurt more, as H2 predicts. The analysis uses the drop, acc(unrelated) − acc(near-duplicate).
4. **Logistic slopes are mostly not estimable.** With 0–3 errors per 60 trials, most bootstrap resamples contain no errors at all, so the slope is undefined; the analysis reports "not estimable" rather than a number.
5. **N = 0 is shared.** The N = 0 surface is identical for all three kinds, so those 12 trials per model were recorded once and replayed for each kind.

## Results
Temperature 0, 12 families × 15 conditions × 2 models = 360 trials. First passes had 19 (20b) and 4 (120b) connection errors; the second pass re-sent them, leaving 0 errors.

| Kind | Model | N=0 | N=5 | N=10 | N=20 | N=50 |
|---|---|---|---|---|---|---|
| unrelated | 20b | 100% | 100% | 100% | 100% | 100% |
| same-domain | 20b | 100% | 100% | 100% | 100% | 100% |
| near-duplicate | 20b | 100% | 100% | 100% | 100% | 91.7% |
| unrelated | 120b | 100% | 100% | 100% | 100% | 91.7% |
| same-domain | 120b | 100% | 100% | 100% | 100% | 91.7% |
| near-duplicate | 120b | 100% | 100% | 83.3% | 91.7% | 100% |

Each cell is 12 trials. Prompt size grows from about 300 tokens at N = 0 to about 1,500 at N = 50.

**Verdicts**
- **H1: not confirmed.** 20b's near-duplicate slope is not estimable (one error, at N = 50). 120b's is +0.14 log-odds per 10 distractors [−0.09, +0.32], not negative, and its errors are at N = 10 and 20, not N = 50, so accuracy is not monotonic in N.
- **H2: not confirmed.** Drop at N = 20, unrelated minus near-duplicate: 20b 0.0 [0.0, 0.0]; 120b +8.3 pp [0.0, +25.0]; McNemar p = 1.0 for both.
- **H3 (exploratory): not testable**, since neither model has an estimable slope.
- **Cost:** a 5× larger prompt at N = 50 bought no measurable accuracy loss on this surface.

**The 6 errors** (5 to a distractor, 1 refusal): 20b chose `web_search_13` for a web search (near-duplicate, N = 50); 120b chose `compose_email_9` for two send-email requests (near-duplicate, N = 10), `web_search_13` for a search (near-duplicate, N = 20), `get_timezone_6` for a calendar request (unrelated, N = 50), and declined to call a tool once (same-domain, N = 50). Several of these distractors could arguably do the requested job, so some of these "errors" may be defensible choices rather than confusion.

Like EXP-003 and EXP-004, this design is limited by goodserver being easy: its five tools are distinct, so distractors rarely compete. The near-duplicate problem seen in EXP-001 comes from tools that are near-duplicates of each other *and* of the request; padding a clear surface does not recreate it.
