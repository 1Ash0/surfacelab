# EXP-004 — Cross-Server Collision and Namespacing

**Status:** run and analysed. **H1 not confirmed** (no cross-server collisions in any condition); H2 and H3 untestable as a result (see Results)  
**Milestone:** M4  
**Label:** numbers in Results trace to `results/exp004_analysis.json` (from `scripts/analyze_exp004.py`, replay plus cached embeddings).

---

## Question
When servers are loaded together, which tool pairs steal each other's tasks, and does namespacing reduce that?

## Hypotheses
- **H1 (confirmatory):** Cross-server collision rate under `namespacing=none` is > 0.10.
- **H2 (confirmatory):** `prefix` namespacing reduces collision rate vs `none`.
- **H3 (confirmatory):** Pairwise description embedding cosine similarity is positively correlated with pairwise cross-server confusion rate (Spearman, permutation-test p).
- **H4 (exploratory):** `qualified` namespacing reduces collision further than `prefix`.

## Design

| Factor | Values |
|---|---|
| Merged surfaces | `merged_none`, `merged_prefix`, `merged_qualified` |
| Constituent servers | `goodserver` (5), `badserver` (5), `siblings` (4) → 14 tools total |
| Model | `openai/gpt-oss-20b` (Groq), `openai/gpt-oss-120b` (Groq) |
| Cases | `fixtures/cases/cross_server.jsonl` (12 families) |
| Variants | canonical order only |

Total: 12 × 3 surfaces × 2 models = **72 trials**

## Primary outcome
Cross-server collision rate = fraction of trials where the emitted tool belongs to a different server than the gold server. Per-surface CI (Wilson, since trials are independent across the three merge conditions for a given case).

## Predictive test (H3)
1. Embed all tool descriptions using `text-embedding-3-small` via OpenRouter (or Gemini embedding endpoint).
2. Compute 14×14 cosine similarity matrix.
3. For each off-diagonal pair (i, j from different servers), record confusion rate from the `none` condition.
4. Spearman ρ between similarity and confusion rate, permutation-test p (10,000 permutations). Pre-declared embedding model: first run uses OpenRouter `text-embedding-3-small`; replicated with a second model to check robustness.

## Multiple comparisons
H1, H2, H3 are confirmatory. H4 is exploratory.

## Surfaces (generated by scripts/gen_fixtures.py)
- `fixtures/surfaces/merged_none.json`
- `fixtures/surfaces/merged_prefix.json`
- `fixtures/surfaces/merged_qualified.json`

## Cases
`fixtures/cases/cross_server.jsonl` — gold is server-qualified (e.g. `goodserver/get_weather`). Grader uses qualified tool name for matched cases; unqualified comparison for the `none` condition.

## Analysis plan
1. Run all 72 trials.
2. For each trial, classify: hit (correct server + tool), cross-server-collision (wrong server), within-server-confusion (right server, wrong tool), miss (no call).
3. Compute collision rate per (surface, model).
4. Spearman ρ for H3 with permutation p.
5. Report McNemar for H2 (paired, matched on case).

## Verdict rule
- **H1 confirmed:** collision rate CI lower bound > 0.10 in `none` condition.
- **H2 confirmed:** collision rate in `prefix` significantly lower than `none` (McNemar p < 0.05, Holm-corrected).

## Budget cap
`--max-usd 2.00`

## Deviations
1. **Temperature 0** (`--temperature 0`); not specified in the plan. See EXP-001 deviation 1.
2. **Scoring done in the analysis, not the runner.** The built-in grader compares against server-qualified gold names, so it scores every `none` and `prefix` answer as wrong. The analysis maps each emitted name back to its server and tool.
3. **Replication embedding model:** `gemini-embedding-001` (Gemini's `text-embedding-004` is no longer available).
4. **"miss" includes malformed tool names.** When the model calls a name that is not in the list, Groq rejects the call (`tool_use_failed`) and it is recorded as no call.

## Results
Temperature 0, canonical order, 12 cases × 3 surfaces × 2 models = 72 trials, 0 errors. Collision rate CIs are Wilson 95%.

| Condition | Model | Hit | Cross-server collision | Wrong tool, same server | Miss |
|---|---|---|---|---|---|
| none | 20b | 5 | **0** [0.00, 0.24] | 4 | 3 |
| none | 120b | 6 | **0** [0.00, 0.24] | 3 | 3 |
| prefix | 20b | 7 | **0** [0.00, 0.24] | 3 | 2 |
| prefix | 120b | 6 | **0** [0.00, 0.24] | 3 | 3 |
| qualified | 20b | 5 | **0** [0.00, 0.24] | 4 | 3 |
| qualified | 120b | 3 | **0** [0.00, 0.24] | 1 | 8 |

**Verdicts**
- **H1: not confirmed.** No answer in any condition went to the wrong server; the collision-rate CI lower bound is 0, not above 0.10.
- **H2: untestable.** With zero collisions under `none`, there is nothing for `prefix` to reduce (McNemar p = 1.0).
- **H3: untestable.** All 111 cross-server confusion rates are 0, so the correlation is undefined for both embedding models.
- **H4 (exploratory):** no collisions to compare.

**What the errors were instead**
- **Wrong tool on the same server** (3–4 cases per condition): mostly the sibling file tools (`locate_files`, `query_files` → `search_files`) and badserver's `fetch_document`/`get_document` pair. This is the near-duplicate problem from EXP-001, not a cross-server one.
- **Clarifying questions:** x007 ("email the team", no address), x009 and x010 (vague badserver tasks) led both models to ask for missing information instead of calling a tool, in every condition. These cases are underspecified.
- **Qualified names broke 120b (exploratory):** under `server/tool` names, 120b missed 8 of 12, versus 3 under the other schemes, because it often called a name that does not exist: the bare tool name (`search_web`) or a dot separator (`siblings.search_files`). 20b was unaffected. Slash-qualified names can cost accuracy for some models even with no collisions to prevent.

These 12 cases are mostly unambiguous across servers, so the design cannot produce collisions. Testing collision needs cases whose request plausibly fits tools on two servers, which none of these do except x003/x004 (file read vs document fetch), and those did not collide.
