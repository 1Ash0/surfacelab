# EXP-001 — Order Sensitivity (Position Bias)

**Status:** preregistered — not yet run  
**Milestone:** M2  
**Label:** [unverified] until data collected; all numbers here are plans.

---

## Question
How much does selection accuracy depend on where the correct tool sits in the list?

## Hypotheses (confirmatory unless labelled exploratory)
- **H1 (confirmatory):** Accuracy is higher when the correct tool appears in the first third of the list than in the last third. (Direction from BiasBusters position-bias findings.)
- **H2 (confirmatory):** The position effect is larger on the `siblings` surface (near-duplicate tools) than on `goodserver` (distinct tools).
- **H3 (confirmatory):** The position effect is smaller for the larger model (`llama-3.3-70b-versatile`) than for the smaller (`llama-3.1-8b-instant`).
- **H4 (exploratory):** Per-case flip rate under reordering is higher for cases with higher lexical overlap between request and tool description.

## Design

| Factor | Values |
|---|---|
| Surface | `goodserver` (5 tools), `siblings` (4 tools) |
| Model | `llama-3.1-8b-instant` (Groq), `llama-3.3-70b-versatile` (Groq) |
| Permutations (k) | `goodserver`: all 5! = 120 orderings; `siblings`: all 4! = 24 orderings |
| Cases | `fixtures/cases/core.jsonl` (15 cases) + `fixtures/cases/siblings.jsonl` (8 cases) |
| Trials per (case, variant) | 1 (temperature fixed; repeats add little at T=0) |

Total trials: (15 × 120 + 8 × 24) × 2 models = 3,600 + 384 = **3,984 trials**

## Primary outcome
Gap in hit rate between correct tool in the first third vs last third of the list, with 95% clustered bootstrap CI (10,000 resamples over families). Reported in percentage points.

## Secondary outcomes
- Cochran's Q across three position-thirds (exploratory).
- Per-case flip rate: fraction of permutation pairs where chosen tool differs.
- Accuracy stratified by lexical overlap tercile (exploratory).

## Sample size and power
Power simulation (`scripts/power_sim.py`, seed=42):  
`p0=0.70, delta=0.08, k=4 variants, n_sim=200` → **30 families needed** for mean clustered CI half-width ≤ 0.08.  
With 23 case families (15 core + 8 siblings) the half-width is expected to be ~0.09–0.10. Acceptable given the large k (120/24 permutations give more signal per family than k=4). Revisit if CI is too wide post-hoc.

## Models and exact ids
- `llama-3.1-8b-instant` via Groq (`GROQ_API_KEY`)
- `llama-3.3-70b-versatile` via Groq (`GROQ_API_KEY`)

- `tool_choice = "required"` (standard for positive/sibling cases)
- `tool_choice = "auto"` for abstain cases (not included in EXP-001)

## Rendering used
`render.py` — OpenAI tool-param format (function calling). Exact bytes logged in cassettes. Reported in results file.

## Cases and split
All 23 families used for estimation (no held-out split in EXP-001; order is the treatment, not descriptions). Leakage risk is low because the gold tool does not change between permutations.

## Analysis plan
1. For each (case, permutation), record the emitted tool name.
2. Assign each trial to a position-third bin based on the gold tool's index in that permutation.
3. Compute per-bin accuracy. Compute gap = acc(first_third) − acc(last_third) with 95% clustered bootstrap CI.
4. Report Cochran's Q across three bins (exploratory, labelled).
5. Report per-model results separately; test H3 via McNemar on matched (case, position_bin) pairs.

## Verdict rule (pre-declared)
- **position_effect_confirmed:** gap CI lower bound > 0 for both models.
- **position_effect_absent:** gap CI upper bound < 0.05 for both models (null result is acceptable and publishable).
- **mixed:** models diverge in direction.
