# EXP-001 — Order Sensitivity (Position Bias)

**Status:** run and analysed. Verdict under the pre-declared rule: **position_effect_absent** (see Results)  
**Milestone:** M2  
**Label:** numbers in Results trace to `results/exp001_analysis.json` (from `scripts/analyze_exp001.py`, replay only); numbers above Results are the original plan.

---

## Question
How much does selection accuracy depend on where the correct tool sits in the list?

## Hypotheses (confirmatory unless labelled exploratory)
- **H1 (confirmatory):** Accuracy is higher when the correct tool appears in the first third of the list than in the last third. (Direction from BiasBusters position-bias findings.)
- **H2 (confirmatory):** The position effect is larger on the `siblings` surface (near-duplicate tools) than on `goodserver` (distinct tools).
- **H3 (confirmatory):** The position effect is smaller for the larger model (`openai/gpt-oss-120b`) than for the smaller (`openai/gpt-oss-20b`).
- **H4 (exploratory):** Per-case flip rate under reordering is higher for cases with higher lexical overlap between request and tool description.

## Design

| Factor | Values |
|---|---|
| Surface | `goodserver` (5 tools), `siblings` (4 tools) |
| Model | `openai/gpt-oss-20b` (Groq), `openai/gpt-oss-120b` (Groq) |
| Permutations (k) | `goodserver`: all 5! = 120 orderings; `siblings`: all 4! = 24 orderings |
| Cases | `fixtures/cases/core.jsonl` (15 cases) + `fixtures/cases/siblings.jsonl` (8 cases) |
| Trials per (case, variant) | 1 (temperature fixed; repeats add little at T=0) |

Total trials: (15 × 120 + 8 × 24) × 2 models = 3,600 + 384 = **3,984 trials**

## Primary outcome
Gap in hit rate between correct tool in the first third vs last third of the list, with 95% clustered bootstrap CI (10,000 resamples over families). Reported in percentage points.

## Secondary outcomes
- Cochran's Q across three position-thirds (exploratory).
- Per-case flip rate: fraction of permutation pairs where chosen tool differs.
- Accuracy stratified by lexical overlap tercile (exploratory).

## Sample size and power
Power simulation (`scripts/power_sim.py`, seed=42):  
`p0=0.70, delta=0.08, k=4 variants, n_sim=200` → **30 families needed** for mean clustered CI half-width ≤ 0.08.  
With 23 case families (15 core + 8 siblings) the half-width is expected to be ~0.09–0.10. Acceptable given the large k (120/24 permutations give more signal per family than k=4). Revisit if CI is too wide post-hoc.

## Models and exact ids
- `openai/gpt-oss-20b` via Groq (`GROQ_API_KEY`)
- `openai/gpt-oss-120b` via Groq (`GROQ_API_KEY`)
- Provider config: `src/surfacelab/providers/openai_compat.py` — PROVIDER_CONFIGS["groq"]
- `tool_choice = "required"` (standard for positive/sibling cases)
- `tool_choice = "auto"` for abstain cases (not included in EXP-001)

## Rendering used
`render.py` — OpenAI tool-param format (function calling). Exact bytes logged in cassettes. Reported in results file.

## Cases and split
All 23 families used for estimation (no held-out split in EXP-001; order is the treatment, not descriptions). Leakage risk is low because the gold tool does not change between permutations.

## Analysis plan
1. For each (case, permutation), record the emitted tool name.
2. Assign each trial to a position-third bin based on the gold tool's index in that permutation.
3. Compute per-bin accuracy. Compute gap = acc(first_third) − acc(last_third) with 95% clustered bootstrap CI.
4. Report Cochran's Q across three bins (exploratory, labelled).
5. Report per-model results separately; test H3 via McNemar on matched (case, position_bin) pairs.

## Verdict rule (pre-declared)
- **position_effect_confirmed:** gap CI lower bound > 0 for both models.
- **position_effect_absent:** gap CI upper bound < 0.05 for both models (null result is acceptable and publishable).
- **mixed:** models diverge in direction.

## Stopping rule
Fixed n. No optional stopping. If the Groq free tier rate-limits mid-run, pause and resume; cassettes make this safe.

## Budget cap
`--max-usd 5.00` per run. Groq free tier is used; actual cost is $0 unless quota exceeded.

## What would change my mind
A pre-run audit showing the rendering reorders tools internally would invalidate the position assignments. Check: compare `render.py` output order with Surface.tools order before running.

## Deviations
1. **Temperature was not set** in any of the 3,989 recorded requests, so the provider default applied instead of the fixed temperature the design assumed. Variation across orderings therefore mixes position with sampling noise; flip rates are upper bounds on order sensitivity. A follow-up probe (`scripts/probe_determinism.py`, `results/determinism_probe.json`) found temperature 0 is mostly but not fully deterministic on Groq: 7 of 8 repeated-request groups were stable across 5 repeats for each model (3 of 80 answers differed). The siblings runs were repeated at temperature 0 (`results/exp001_siblings_*_t0.json`).
2. **Position thirds were not defined for 4 or 5 tools.** Binned by `floor(3·index/n)` (5 tools: {0,1},{2,3},{4}; 4 tools: {0,1},{2},{3}). First slot vs last slot is reported as a sensitivity check.
3. **20 families, not 23.** The 3 abstain cases (c013–c015) have no gold tool and so no position. They were run with `tool_choice="auto"`, which the plan also specified.
4. **H3 test.** McNemar was run on matched (case, permutation) trials, but it treats trials as independent and tests accuracy, not position effect. The bootstrap difference in gaps is the direct H3 test.
5. **Refusals scored incorrect.** 5 trials where the model declined or wrote malformed tool arguments (Groq 400 `tool_use_failed`) were originally retried away; the original outcomes were restored from first-pass run logs and scored incorrect.

## Results
Clustered bootstrap over case families, 10,000 resamples, seed 42. Gap = accuracy(first third) − accuracy(last third), in percentage points.

| | 20b | 120b |
|---|---|---|
| Accuracy by third (first / middle / last) | 90.5 / 94.1 / 89.3% | 91.4 / 95.0 / 90.5% |
| **H1 gap, pooled** | +1.2 [−0.6, +4.2] | +0.9 [−0.5, +2.8] |
| Gap, goodserver only | 0.0 [0.0, 0.0] (100% at every position) | 0.0 [0.0, 0.0] |
| Gap, siblings only | +8.3 [−4.2, +24.0] | +6.3 [−4.2, +15.6] |
| **H2** (siblings gap − goodserver gap) | +8.3 [−4.2, +24.0] | +6.3 [−4.2, +15.6] |
| Sensitivity: first slot − last slot | +1.5 [−0.3, +4.5] | +2.1 [+0.2, +5.0] |
| Cochran's Q, exploratory (df 2) | 0.67 | 0.00 |

**H3** (20b gap − 120b gap): +0.3 [−2.3, +3.5]. McNemar on matched trials: 120b alone correct 39, 20b alone correct 23, p = 0.056.

**Verdicts**
- **H1: position_effect_absent** under the pre-declared rule (both models' gap CI upper bounds are below 5 pp). This is driven by goodserver, where both models are at ceiling (1,440 of each model's 1,632 trials). On siblings alone the data cannot rule out an effect as large as 24 pp (20b) or 16 pp (120b).
- **H2: not supported.** The siblings gap is larger, but the CIs include zero. With only 8 sibling families, the test is underpowered.
- **H3: not supported.** No difference in position effect between models. The 120b model is more accurate overall (borderline, p = 0.056).
- **H4: not analysed** (exploratory, deferred).

**Flip rates:** every goodserver case has a flip rate of 0 for both models. All 8 sibling cases flip under 20b (0.37–0.77); 6 of 8 flip under 120b (0.37–0.59). Under 120b, s005 is always correct and s006 is always wrong with the same tool: consistent, not order-dependent.
