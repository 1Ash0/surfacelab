# EXP-006 — Server Availability (Sandboxed Handshake Probe)

**Status:** preregistered — ADR-022 accepted; Docker 29.5.2 running (2026-10-28); target list drafted in `fixtures/targets/exp006_targets.json` (19 servers), ADR-024 accepted; **run 2026-10-28**  
**Milestone:** M5  
**Label:** [unverified]

---

## Question
What fraction of MCP servers in a bounded, consented, curated list complete the handshake successfully, and which failure modes are most common?

## Pre-conditions (all must be true before running)
1. ADR-022 accepted — Docker sandbox design confirmed.
2. Target list assembled and reviewed: bounded, curated, consented servers only.
3. Docker daemon running (`docker ps` returns clean output).
4. `probe_docker()` validated on fixture servers (`make exp006-preflight`).

## Design

| Factor | Values |
|---|---|
| Targets | Bounded, curated list (assembled separately; not bulk-crawled) |
| Sandbox | `probe_docker()` with `--network=none`, `--read-only`, `--memory=256m`, `--cpus=0.5`, `--user=1000:1000` |
| Timeout | 10.0 s per server |
| Snapshots | Enabled — drift detection across repeated probes |
| Outcome taxonomy | `ok`, `no_tools`, `spawn_error`, `timeout`, `needs_credentials`, `protocol_error` |

## Primary outcome
Fraction of servers with outcome `ok`, with Wilson CI. Secondary: per-outcome breakdown.

## Safety constraints (non-negotiable; from ADR-007 and ADR-022)
- Never probe a server not on the curated list.
- Never call `tools/call` on any server (ADR-008).
- Never publish a headline "X% of servers are broken" without a defensible sampling frame.
- Report measured n and the list's provenance.
- Each server owner is either the user themselves, or has publicly published the server with open-source licence (consent by publication).

## Instruction-like flags
`instruction_like_flags()` runs on every successful `ok` probe. Results labelled "possible" — FP rate is from EXP-007 (precision=1.000, recall=0.929, FP_rate=0.000).

## Drift detection
Second probe of same servers at a later date; `classify_drift()` reports changes. Labelled "possible drift" until manually reviewed.

## Budget cap
No model calls. Docker container CPU/memory limits act as the cost cap.

The four non-ok outcomes come from our sandbox configuration (no network, placeholder credentials, no repository mounted) as much as from the servers: `git` exits when not given a repository, `stripe` exits on an invalid key, `supabase` lists no tools without a project, `neon` did not answer within 30 s offline. They are **not** evidence that these servers are broken.

**Descriptive, not preregistered: tool-list size.** Rendered with `o200k_base`, the Notion list is 21.7K tokens, Firecrawl 16.6K, MongoDB 15.6K and GitHub (default tools) 13.8K, each larger than one request allowed on the Groq free tier (8K tokens per minute for gpt-oss; 7K input for Qwen). Providers count differently: on the same browser loadout, Groq reported 3,493 prompt tokens for gpt-oss and 6,232 for Qwen (`results/exp013_prompt_tokens.json`).

## Second probe (drift), planned
The preregistration calls for a second probe at a later date. Because this run pinned every version, re-probing the same images can only show no drift. The second probe therefore rebuilds the images from each package's **latest** release (still `--ignore-scripts`, same sandbox and placeholder credentials) and compares tool lists with `classify_drift()` against `runs/exp006/snapshots/`. Planned for **2026-11-11** (two weeks), so releases have time to land; outcomes labelled "possible drift" until reviewed.

## Deviations
- **Windows timeout bug fixed before the counted run.** The first attempt hung: on Windows, `_recv` had no timeout, so a silent server blocked forever. Fixed with a reader thread (`src/surfacelab/pulse.py`) and a two-sided test (`tests/test_u12.py::test_silent_server_times_out`). Only the rerun is reported.
- Servers needing a credential got the literal placeholder `surfacelab-placeholder`; npm packages were installed with `--ignore-scripts` (`docker/exp006/`).
- Timed-out servers were probed once more at 30 s only to collect snapshots; that pass is not part of the primary outcome.
