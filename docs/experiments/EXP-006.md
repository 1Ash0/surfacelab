# EXP-006 — Server Availability (Sandboxed Handshake Probe)

**Status:** preregistered — ADR-022 accepted; Docker 29.5.2 running (2026-10-28); target list drafted in `fixtures/targets/exp006_targets.json` (19 servers), **awaiting review and ADR-024**  
**Milestone:** M5  
**Label:** [unverified]

---

## Question
What fraction of MCP servers in a bounded, consented, curated list complete the handshake successfully, and which failure modes are most common?

## Pre-conditions (all must be true before running)
1. ADR-022 accepted — Docker sandbox design confirmed.
2. Target list assembled and reviewed: bounded, curated, consented servers only.
3. Docker daemon running (`docker ps` returns clean output).
4. `probe_docker()` validated on fixture servers (`make exp006-preflight`).

## Design

| Factor | Values |
|---|---|
| Targets | Bounded, curated list (assembled separately; not bulk-crawled) |
| Sandbox | `probe_docker()` with `--network=none`, `--read-only`, `--memory=256m`, `--cpus=0.5`, `--user=1000:1000` |
| Timeout | 10.0 s per server |
| Snapshots | Enabled — drift detection across repeated probes |
| Outcome taxonomy | `ok`, `no_tools`, `spawn_error`, `timeout`, `needs_credentials`, `protocol_error` |

## Primary outcome
Fraction of servers with outcome `ok`, with Wilson CI. Secondary: per-outcome breakdown.

## Safety constraints (non-negotiable; from ADR-007 and ADR-022)
- Never probe a server not on the curated list.
- Never call `tools/call` on any server (ADR-008).
- Never publish a headline "X% of servers are broken" without a defensible sampling frame.
- Report measured n and the list's provenance.
- Each server owner is either the user themselves, or has publicly published the server with open-source licence (consent by publication).

## Instruction-like flags
`instruction_like_flags()` runs on every successful `ok` probe. Results labelled "possible" — FP rate is from EXP-007 (precision=1.000, recall=0.929, FP_rate=0.000).

## Drift detection
Second probe of same servers at a later date; `classify_drift()` reports changes. Labelled "possible drift" until manually reviewed.

## Budget cap
No model calls. Docker container CPU/memory limits act as the cost cap.
