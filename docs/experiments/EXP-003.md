# EXP-003 — Single-Edit Tradeoff

**Status:** preregistered — not yet run  
**Milestone:** M3  
**Label:** [unverified] until data collected.

---

## Question
For each description edit, what happens to selection accuracy?

## Hypotheses
- **H1 (confirmatory):** `add_usage_clause` improves accuracy vs base on `goodserver` for cases where the request matches the usage clause.
- **H2 (confirmatory):** `goodserver_set_desc_vague` (set_description to "Creates an event.") regresses accuracy for `create_calendar_event` cases.
- **H3 (exploratory):** `trim_to_first_sentence` does not significantly change accuracy when the first sentence is informative.

## Design

| Factor | Values |
|---|---|
| Base surface | `goodserver` |
| Edit surfaces | `goodserver_add_usage`, `goodserver_add_negation`, `goodserver_prepend_summary`, `goodserver_trim`, `goodserver_set_desc_vague` |
| Model | `llama-3.1-8b-instant` (Groq), `llama-3.3-70b-versatile` (Groq) |
| Variants | canonical order only (edit is the treatment; order swept in EXP-001) |
| Cases | `fixtures/cases/core.jsonl` (15 families) |

Total: 15 × 6 surfaces × 2 models = **180 trials**

## Primary outcome
Paired accuracy delta vs base (McNemar, matched on case family), with clustered paired-difference CI. Reported per edit.

## Multiple comparisons
5 edits = 5 tests. Pre-declared family: {add_usage_clause, add_negation_clause, prepend_summary, trim_to_first_sentence, set_description}. Holm correction for confirmatory claims (H1 and H2 only). The remaining 3 edits are exploratory and labelled so.

## Overfitting guard
Edits evaluated on held-out families. Split: families c001–c010 are train (not used for evaluation); c011–c015 are evaluation. (In EXP-001 all families were used; here the edit was designed on the training split.)

## Verdict rule (per edit, pre-declared)
- **helps:** CI lower bound > +0.05 (5 pp improvement).
- **regresses:** CI upper bound < -0.05.
- **costs:** accuracy flat (CI contains 0) but description token count increased > 20%.
- **inconclusive:** otherwise.

Token delta computed exactly from `render.py` output on base vs edited surface.
