# EXP-011 — Cross-Server Collision with Overlapping Servers (follow-up to EXP-004)

**Status:** preregistered and approved (2026-10-28); gold validated; **run and analysed 2026-10-28**  
**Milestone:** M4 follow-up  
**Label:** all numbers below are plans or come from earlier results files, which are cited.

---

## Question
When two loaded servers offer overlapping tools, how often does the model pick the right capability from the wrong server, and does namespacing help?

## Why
EXP-004 saw zero cross-server collisions in 72 trials because no request plausibly fit tools on two servers (`results/exp004_analysis.json`). It also found that slash-qualified names (`server/tool`) made 120b call non-existent tools in 8 of 12 cases.

## Hypotheses
- **H1 (confirmatory):** With overlapping servers and no namespacing, the cross-server collision rate is above 0.10.
- **H2 (confirmatory):** `prefix` namespacing (`server_tool`) lowers the collision rate versus `none`.
- **H3 (exploratory):** Under slash-qualified names, 120b's rate of calls to non-existent tools exceeds its rate under `prefix` (replicating the EXP-004 observation).

## Design

| Factor | Values |
|---|---|
| Servers | 3 pairs of overlapping servers with identical tool names, 3 tools per server: `local_fs`/`cloud_drive`, `work_mail`/`personal_mail`, `team_wiki`/`public_web` (`fixtures/surfaces/xo_<pair>_<scheme>.json`) |
| Cases | `fixtures/cases/cross_overlap.jsonl`: **24 families**, 8 per pair, 4 per server. Each request names a detail (this computer, cloud drive, work account, gmail, internal wiki, a URL) that makes exactly one server correct |
| Namespacing | `none`, `prefix`, `qualified` (slash) |
| Models | `openai/gpt-oss-20b`, `openai/gpt-oss-120b` |
| Orderings | 2 orderings per surface: server A's tools first, then server B's first |
| Temperature | 0 |

Total: 24 × 3 × 2 × 2 = **288 trials**.

**`none` uses an uninformative suffix.** With identical names (both servers' `search_files`), the emitted name could not show which server was meant, so collisions would be unmeasurable. The second server's tools are named with `_2` (`search_files`, `search_files_2`), much as clients dedupe clashing names, so only the description tells the servers apart.

## Classification
Each trial is one of: hit, cross-server collision (right capability, wrong server), within-server error, call to a non-existent tool, or no call. Scored by `scripts/analyze_exp004.py` logic, extended with the non-existent-tool class.

## Primary outcome
Collision rate per (namespacing, model), Wilson 95% CI over trials, with a clustered bootstrap over families as a sensitivity check (two orderings per family are not independent).

## Verdict rule
- **H1 confirmed:** collision-rate CI lower bound > 0.10 under `none`, for at least one model.
- **H2 confirmed:** McNemar p < 0.05 (Holm across H1/H2 tests per model), `prefix` lower than `none`.

## Budget cap
`--max-usd 2.00` per run.

## Results (2026-10-28)

Source: `results/exp011_analysis.json` (`scripts/analyze_followups.py --exp 11`); trials in `results/exp011_{20b,120b}.json`. 144 trials per model, 0 errors.

| Model | Scheme | Hit | Collision | Within-server | Non-existent | No call | Collision rate [Wilson 95%] |
|---|---|---|---|---|---|---|---|
| 20b | none | 42 | 1 | 4 | 0 | 1 | 2.1% [0.4%, 10.9%] |
| 20b | prefix | 46 | 0 | 2 | 0 | 0 | 0.0% [0.0%, 7.4%] |
| 20b | qualified | 45 | 0 | 3 | 0 | 0 | 0.0% [0.0%, 7.4%] |
| 120b | none | 44 | 0 | 4 | 0 | 0 | 0.0% [0.0%, 7.4%] |
| 120b | prefix | 41 | 0 | 5 | 0 | 2 | 0.0% [0.0%, 7.4%] |
| 120b | qualified | 40 | 0 | 5 | 0 | 3 | 0.0% [0.0%, 7.4%] |

**Verdicts.** H1 not confirmed for either model: one collision in 288 trials (20b, `none`); the CI lower bound is far below 0.10. H2 not confirmed (McNemar p = 1.0 for both; one discordant pair for 20b, none for 120b). H3 (exploratory) not replicated: 120b made **no** calls to non-existent tools under slash-qualified names here, unlike 8 of 12 in EXP-004.

**Interpretation.** When a request names a distinguishing detail (this laptop, gmail, the internal wiki), both models pick the right server even when only the description tells the servers apart. Remaining errors are within-server (wrong operation) or no call, not collisions. The EXP-004 slash-name failure did not recur on these surfaces, so it should not be cited as a general 120b behaviour [unverified beyond EXP-004's surface].

## Deviations
- Gold is written in `server/tool` form and remapped per scheme at run time (`_remap` in `scripts/run_followups.py`); every remapped gold name was checked to exist on its surface before the run.
- H2 McNemar is run on the matched (family, ordering) collision indicator; with one test per model Holm leaves p unchanged.
