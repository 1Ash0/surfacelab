# EXP-013 — Which Server Wins? Tool Choice on Real MCP Server Loadouts

**Status:** preregistration revised 2026-10-28 (ADR-025) before any run; loadouts and cases committed; **blocked on gold validation**  
**Milestone:** M5 follow-up  
**Label:** all numbers below are plans, or are measured sizes cited to files. No trial has been run.

---

## Question
When a user installs real MCP servers that can do the same job, which server's tool does the model use, and does that depend on which server is listed first? And when only one server's tool fits, does the model still find it?

## Why
Across EXP-001, EXP-009 and the EXP-014 replication on Qwen, one effect held in both model families: when two or more tools could do the job, the model favoured whichever was listed first (+10.4 pp on gpt-oss-120b, `results/exp001_siblings_t0_analysis.json`; +12.5 pp on Qwen, `results/exp014_analysis.json`). When each tool had a distinct scope, accuracy was 99–100% (`results/exp009_analysis.json`). Those surfaces were ours. Real servers overlap constantly (two browser servers both navigate; three search servers all search), so this tests whether **list order decides which real server gets used**.

## Hypotheses
- **H1 (confirmatory): order decides ties.** On *shared* cases, where gold validation accepts tools from two or more servers, the server listed first is chosen more often than chance: first-listed share > 1/k, where k is the number of servers with an accepted tool.
- **H2 (confirmatory): unique tools are still found.** On *unique* cases (exactly one server's tool accepted), accuracy is at least 0.90.
- **H3 (exploratory):** On shared cases, how often the chosen server changes when server order changes (flip rate), per model and loadout; and whether the three models prefer the same server when order is held fixed.
- **H4 (exploratory):** On unique-case errors, whether the wrong tool is more similar to gold than other tools (`surfacelab.similarity`).

## Loadouts
Built by `scripts/build_exp013_loadouts.py` from sandboxed `tools/list` probes (ADR-022, ADR-008): names, descriptions and schemas verbatim, committed as `fixtures/surfaces/real_*.json` with a tool → server map, before cases were written.

| Loadout | Servers (maintainer) | Tools | Shared jobs |
|---|---|---|---|
| browser | Playwright (Microsoft, all 25 tools); Chrome DevTools (Google, navigation category, 6) | 31 | navigate, back, new tab, list tabs, close tab, wait for text |
| web | Brave Search (web + news); Tavily (all 5); DuckDuckGo (all 3) | 10 | web search (all three), news, read a page |
| workspace | Filesystem (MCP steering group, all 14); Git (MCP steering group, all 12); GitHub (GitHub, 7 file and history tools) | 33 | read a file in a local repo |
| docs | Context7 (Upstash); AWS Documentation (AWS Labs); Fetch (MCP steering group) | 8 | read an AWS docs URL |

**Size cap.** Each request must fit every model's free-tier limit (Qwen: 7,000 input tokens per minute; gpt-oss: 8,000 tokens per minute). Cap: 6,500 provider-reported prompt tokens. Measured (`results/exp013_prompt_tokens.json`), Qwen / gpt-oss: browser 6,232 / 3,493; web 6,165 / 4,292; workspace 6,277 / 3,382; docs 5,300 / 4,441. Tools were selected only through each server's documented options (`--enabled-tools`, `--tools`, `--category*`); no tool was edited.

## Cases
`fixtures/cases/real_loadouts.jsonl`: **48 families**, 12 per loadout. 16 are written as *shared* (browser 6, web 6, workspace 1, docs 3) and 32 as *unique*; the label in each note is the author's, and gold validation decides the final class (a case becomes shared if the validator accepts tools from two or more servers). No request contains a tool name (checked by `scripts/gen_exp013_gold_sheet.py`).

**Gold validation (ADR-023 procedure).** A person who did not write the cases fills `fixtures/cases/gold_validation_exp013.csv`: one row per case and candidate tool, with the full tool description, marked y or n. Loadouts of up to 10 tools show every tool; larger ones show 8 candidates per case (gold first, then word overlap, then random), shuffled with seed 42. Disagreements are resolved before any run and logged.

## Design

| Factor | Values |
|---|---|
| Models | `openai/gpt-oss-20b`, `openai/gpt-oss-120b`, `qwen/qwen3.8-27b` (Groq) |
| Server order | every cyclic rotation of the server blocks (browser 2; web, workspace, docs 3); tool order within a server is the server's own |
| Temperature | 0 |
| Refusals | recorded, scored incorrect |

Total: (12 × 2 + 36 × 3) = 132 trials per model, **396 trials**.

## Analysis
- H1: per model, first-listed share = fraction of shared-case trials whose chosen tool belongs to the server listed first, among trials that chose an accepted tool. Clustered bootstrap over families (10,000, seed 42). Chance is the mean of 1/k over those trials.
- H2: per model, accuracy on unique cases, clustered bootstrap.
- Holm across the three models within each hypothesis.

## Verdict rule (per model)
- **H1 confirmed:** CI lower bound of (first-listed share − chance) > 0. **Absent:** CI upper bound < 0.05. Otherwise inconclusive.
- **H2 confirmed:** accuracy CI lower bound ≥ 0.90. **Not confirmed:** CI upper bound < 0.90. Otherwise inconclusive.

## Reporting rule
Results describe what models do when servers overlap, e.g. "with Playwright and Chrome DevTools installed together, the server listed first handled X% of navigation requests". They never say a server is worse. Server preference (H3) is reported as a property of the model and the descriptions together. Every quoted description comes from a committed snapshot.

## Budget cap
`--max-usd 3.00` per model. Estimated tokens: about 4,000 × 132 ≈ 0.53M per gpt-oss model and 6,000 × 132 ≈ 0.79M for Qwen [estimate from measured prompt sizes].

## What was left out, and why
- **Firecrawl** (16.6K tokens) and **Notion** (21.7K) have no tool-selection option and do not fit alone. **Desktop Commander** (about 10K) likewise.
- **Chrome DevTools' screenshot and debugging tools**: they would overlap Playwright's, but Playwright cannot be trimmed and the pair would exceed the Qwen limit. Navigation is the overlap that fits.
- **Databases**: of Supabase, Neon and MongoDB only MongoDB started in the sandbox, and it alone is 15.6K tokens.
- `memory`, `time`, `sequential-thinking`: no overlap with the rest.
